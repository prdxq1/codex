# Лабораторная работа № 2. Цифровая обработка изображений

Первые два варианта задания (объём для оценки «удовлетворительно»):
1. Выделение контуров: Лаплас, Робертс, Собел.
2. Подавление гауссова шума: прямоугольное усреднение 3×3 и 5×5, гауссово усреднение 5×5 (σ=1,5).

## Готовые результаты

- [Отчёт DOCX](report/Лабораторная%20работа.docx).
- [Отчёт PDF](report/Лабораторная%20работа.pdf), готовый к просмотру и печати.
- `test_input/clean.png` — программно созданный эталон.
- `test_input/input.png` — эталон с гауссовым шумом σ=25, seed=42.
- `test_output/` — результаты обработки, контуры чистого эталона для сравнения и `metrics.csv`.

На титульном листе указано **Дутов Р. В.**; группа не указана. Для изменения данных:

```sh
python -m pip install -r requirements-report.txt
python tools/build_report.py --name 'Фамилия И. О.' --group 'Номер группы'
python tools/export_pdf.py
```

Для экспорта нужны LibreOffice **Writer и Math** (Math обеспечивает отображение формул) и `pdftotext` из poppler-utils. PDF фиксирует результат вёрстки; другой редактор или набор шрифтов может изменить переносы DOCX. Стили, поля, абзацные отступы, формулы и колонтитулы с PAGE взяты из предоставленного отчёта Кузьменко. Оглавление приведено к двум вариантам, номера согласованы с PDF. Для другой пагинации можно передать `--pages file.json` при сборке отчёта: JSON-массив из девяти номеров разделов в порядке оглавления.

## Сборка и запуск

Требуются C++17, GNU Make и компилятор g++ (или clang++). Внешние C++-зависимости включены в `include/`; интернет при сборке не нужен.

```sh
make -j2
make test
make run
```

### Windows: готовое решение Visual Studio

1. Скачайте репозиторий целиком (**Code → Download ZIP**) и распакуйте архив.
2. Откройте **`CodexLab.sln`** в Visual Studio 2022 или новее.
3. Нажмите **Ctrl+F5** («Запуск без отладки»); при запросе сборки нажмите «Да».

Проект **CodexLab** стоит первым в решении и предназначен для запуска программы. Если Visual Studio сохранила другой запускаемый проект, нажмите правой кнопкой на **CodexLab → Назначить запускаемым проектом**. Отдельный **CodexLabTests** запускает тесты.

C++17, пути к заголовкам, отсутствие предкомпилированных заголовков и рабочая папка уже настроены. `test_input` и `test_output` создаются в корне распакованного репозитория. При повторном запуске картинки генерируются заново. Исполняемые файлы попадают в `bin/vs/`, промежуточные — в `build/vs/`. Доступны Debug/Release и x64/Win32.

В Visual Studio нужен установленный компонент **«Разработка классических приложений на C++»**, включая MSVC и Windows SDK. Скачивать только `.sln` отдельно нельзя: рядом нужны проекты, `src` и `include`. GNU Make для запуска через Visual Studio не требуется.

Файлы решения проверены структурно в Linux; сборка MSVC и запуск на Windows в этой среде не выполнялись.

`make run` **заново генерирует** все входные изображения и результаты. Никакие фотографии из приложенных архивов не загружаются. На светлом фоне создаются треугольник, ромб, эллипс и крест. Композиция отличается от сцены в архивном примере. Одинаковый seed воспроизводит шум при одинаковой реализации стандартной библиотеки C++; `normal_distribution` может различаться между платформами.

`Image` поддерживает PNG, каналы 1–4, безопасный доступ вне границ и глубокое копирование. Его интерфейс не расширялся. Для 1–2 каналов `getColor` записывает яркость в `r`, оставляя `g` и `b` без изменения, как в предоставленных тестах. Для границ фильтров применяется репликация крайнего пикселя. Амплитуды контуров ограничиваются 255, без масштабирования по максимуму изображения.

## Проверка

В текущей среде: **16 тестов, 547 утверждений, все пройдены**. В исходных тестах неинициализированные переменные `g,b` заменены нулями, иначе сравнение с ними имело неопределённое поведение; проверяемые требования сохранены. Добавлены проверки импульсного отклика, постоянного изображения, симметрии Гаусса, границ и неверных параметров.

| Метод | MSE по всему изображению | PSNR, дБ | MSE на плоском фоне |
|---|---:|---:|---:|
| Зашумлённый вход | 614,5460 | 20,2453 | 620,8910 |
| Усреднение 3×3 | 119,2950 | 27,3646 | 74,7996 |
| Усреднение 5×5 | 113,9490 | 27,5637 | 34,8829 |
| Гаусс 5×5 | 96,6393 | 28,2793 | 38,2121 |

На новой композиции наименьшая общая MSE получена фильтром Гаусса (96,6393), а наименьшая ошибка на ровном фоне — прямоугольным окном 5×5. Ошибки измеряются относительно чистого эталона. Область фона: 5 ≤ x < 25, 110 ≤ y < 230. Сильнейшее сглаживание не обязательно даёт лучшую общую ошибку: оно размывает границы и узкие полосы.

## Происхождение материалов

Просмотрены все три вложения: `KG_1.rar` (условие, требования Image, исходный каркас, тесты, пример отчёта), `VSC_Last.7z` (пример реализации и структуры проекта), `Кузьменко Е.А. отчет.docx` (шаблон оформления). Решение адаптировано из предоставленного VSC-проекта: удалён вариант 3, заменён запуск, добавлены генерация эталона, измерения, тесты и переносимая сборка. Готовые PNG и Windows-бинарники из архивов в решение не переносились.

`tools/report_template.docx` содержит адаптированный шаблон с автоматически созданными иллюстрациями. `tools/report_text.json` содержит заново сформулированные пояснения и выводы при неизменной структуре разделов. `tools/build_report.py` применяет этот текст и обновляет титульный лист, метрики и рисунки. В приложениях А и Б отчёта приведён фактически используемый код фильтров; полный исходный код расположен в `src/`.

Библиотеки stb и doctest поставлены из предоставленных материалов; уведомления об их лицензиях сохранены в заголовках. Получение оценки зависит от проверки и защиты работы преподавателем.
